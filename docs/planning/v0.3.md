### P0 Security Candidates (Sentinel)

**T4: CodeQL Python language matrix** (HIGH severity, S effort)

- CodeQL workflow (`.github/workflows/codeql.yml:21`) scans only `actions`, not Python source. The Python codebase (server, audit, scorecard, azure_client) is the primary attack surface but is invisible to CodeQL. The passing "CodeQL" status check gives false coverage confidence.
- Fix: Add `python` to the `language` matrix. One-line workflow change. Highest signal-to-effort ratio in the wave.
- Source: Sentinel finding T4 (`.squad/decisions/inbox/sentinel-v03-research-threat-delta.md`, "T4 (NEW): CodeQL workflow scans only `actions`, not Python source").
- Owner: **Sentinel**.
- Dependencies: None. Should land first to surface pre-existing findings before other PRs.

**T2: manifest.json integrity hash** (HIGH severity, S effort)

- `verify_query_integrity.py` checks `.kql` file hashes against `manifest.json`, but `manifest.json` itself is the root-of-trust and has no signature or hash. An attacker who modifies manifest metadata (text, category, citation) can inject content into AI agent prompts while SHA verification passes.
- Fix: Compute SHA-256 of `manifest.json` itself and pin in `data/alz-queries/.manifest.sha256`. Refresh workflow regenerates the pinned hash. CI step asserts equality.
- Source: Sentinel finding T2 (`.squad/decisions/inbox/sentinel-v03-research-threat-delta.md`, "T2 (NEW): `manifest.json` bytes are not integrity-checked").
- Owner: **Atlas** (manifest domain) + **Sentinel** (review).
- Dependencies: None. Enables T6 (outputSchema) to be meaningful.

**I4: token_scrub consolidation and missing patterns** (HIGH severity, S-M effort)

- `token_scrub` is duplicated between `audit.py` (4 regex) and `azure_client.py` (2 regex, missing GUID + Bearer). Neither covers: Azure connection strings (`AccountKey`), SAS URL parameters (`?sig=`), User Principal Names (`user@contoso.com`), IPv4/IPv6 addresses, PEM blocks, x-ms-correlation-request-id headers.
- Fix: Consolidate into single `mcp_server_azure_architect.scrub` module. Add regex for connection strings, SAS, UPN, IPv4/IPv6, PEM. Add property-based test (Hypothesis) for coverage fuzzing.
- Source: Sentinel finding I4 (`.squad/decisions/inbox/sentinel-v03-research-threat-delta.md`, "I4 (NEW): `token_scrub` coverage gaps and duplicated definition").
- Owner: **Sentinel**.
- Dependencies: None. Can parallelize with T4 and T2.

- Note: The original A1 candidate was `diagnostics_coverage`, but that query already shipped in #100 (see CHANGELOG: "Custom governance queries for diagnostics coverage and tag audit"). Replaced with Reliability pillar gap to avoid double-listing shipped work.
